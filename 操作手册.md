# QQ Bot Public Operation Manual

[English](#english) | [简体中文](#chinese)

<a id="english"></a>
## English

This manual covers the sanitized public distribution. Adapt paths, service names, QQ identifiers, and providers to your own environment. Never copy private runtime values into the public repository.

## 1. Install

Create a Python 3.12 or 3.13 virtual environment and install the required extras:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[market,video,dashboard]'
cp .env.example .env
cp config/config.example.json config/config.json
```

The `market` extra installs AkShare and yfinance. HiThink, the default A-share primary provider, uses the built-in HTTP client; AkShare is the only configured A-share fallback and uses Tencent Securities. The `video` extra installs yt-dlp and SOCKS proxy support; `dashboard` adds the private web server. Install `ffmpeg` with your operating system package manager before enabling video downloads.

## 2. Configure Secrets And IDs

Keep literal secrets in `.env` or your service manager, never in JSON or scripts:

```dotenv
QQ_BOT_MODEL_API_KEY=
QQ_BOT_HITHINK_API_KEY=
QQ_BOT_ONEBOT_TOKEN=
QQ_BOT_VIDEO_HTTP_PROXY=
QQ_BOT_VIDEO_SOCKS_PROXY=
QQ_BOT_CONFIG_PATH=config/config.json
```

Set these placeholders in `config/config.json`:

```text
BOT_QQ
ROOT_QQ
OWNER_QQ
ALLOWED_GROUP_ID
https://api.example.com/v1
your-model-name
```

Root users automatically have owner and private-allowlist permission. Only root can manage owners or authorize the controlled video-upload acceptance path.

Optional integrations remain disabled until their `enabled` flag and provider settings are configured. Do not treat a configured route as proof that its provider is reachable.

For A-share quotes, the public template configures HiThink as the primary provider and AkShare as the only fallback. Keep `QQ_BOT_HITHINK_API_KEY` empty in `.env.example`; set its actual value only in an ignored `.env` file or service manager. AkShare fallback uses Tencent Securities for batch and name lookups, while an explicit canonical code such as `000001.SZ` uses a Tencent fast path. Missing, non-positive, or suspended prices are treated as unavailable and are never presented as current quotes.

The public `config/persona_profile.example.json` contains numeric demonstration metrics and `SOURCE_QQ` only. Generate an ignored `persona_profile.local.json` for a real deployment, update `persona.profilePath`, and do not commit source identifiers or chat history. Runtime does not fall back to the example profile automatically.

## 3. Connect OneBot

Run the bot:

```bash
.venv/bin/python bot.py
```

Configure NapCat or another OneBot v11 implementation to connect by reverse WebSocket:

```text
ws://127.0.0.1:8081/onebot/v11/ws
```

Use the same access token on both sides. Keep the listener on loopback unless your deployment has a separately reviewed network boundary.

## 4. Help, News, Markets, And Search

The following group features use structured delivery instead of normal short-chat bubbles:

```text
/help
#政事
#财经
#科技
#金融
#A股
#美股
#比亚迪
#牧原股份（牧原）
#chat 查一下 <query> [--page N]
#chat 帮我查一下 <query> [--page N]
```

Behavioral guarantees:

- `/help` is one complete message containing all eight entry lines.
- Each news category sends every non-empty set of verifiable atomic blocks containing a Chinese title, source, Beijing time, and URL.
- Search sends every non-empty set of verifiable atomic blocks containing a Chinese title, source, Chinese summary, and URL. Larger result sets retain the existing paging rules without silently dropping a short tail.
- A-share and US-share commands concurrently fetch 20 sector core stocks in one report. They show sector tendency, data time, source, and command latency without per-stock percentage changes. A-share routing prefers HiThink and fails over only to AkShare; the AkShare fallback uses Tencent Securities for batch/name lookups and a canonical code fast path, while missing or suspended prices remain unavailable.
- URLs, decimals, and common abbreviations are protected from sentence splitting.
- Titles, summaries, times, statuses, and explanations are Chinese. Source names, URLs, and command syntax may retain their original form.
- Complete information messages are attempted first. Only an explicit OneBot message-length rejection triggers one compact-summary retry; other send failures do not trigger this fallback.
- A single external URL is accepted up to 2048 characters. An abnormal longer URL is marked unavailable without splitting its atomic block.

Scheduled news commands:

```text
#新闻订阅
#新闻订阅 HH:MM
#新闻订阅状态
#新闻退订
```

Feeds fail independently. Delivery checkpoints are at-least-once: after a OneBot acknowledgement followed by a process crash before the SQLite cursor commit, the last block can be repeated.

Group chat behavior:

- Group reply routes have no project-level safety classifier. Group text, image understanding/generation, explicit voice, search/evaluation, repeats, stickers, and pending enqueue are not blocked or rewritten by project safety rules. Private chat and low-sensitivity long-term storage keep their existing controls.
- Normal short group calls use at most 320 completion tokens, forward the configured reasoning effort, and use `conversationSessions.groupModelTimeoutSeconds` (default 18 seconds) as a hard deadline. Image understanding uses an independent breaker and `visionTimeoutSeconds` (default 30 seconds).
- A technical topic plus an explanation cue such as "what is", "why", implementation, debugging, or a detailed explanation uses `single_message_long`. The call bypasses the ordinary 320-token cap and sends one complete QQ message without the normal three-bubble truncation rule. Non-technical chat remains short.
- Dormant-session relation checks use at most 32 tokens and `conversationSessions.relationTimeoutSeconds` (default 1.2 seconds).
- Triggered OneBot images resolve a fresh URL with `get_image`, allow only trusted QQ CDN HTTPS downloads up to 8 MiB, and inline JPEG/PNG; GIF/WebP are converted to a bounded PNG first frame with ffmpeg. Successful visual analysis returns a controlled semantic sticker intent: the bot sends one matching safe local sticker, excludes the incoming asset, and sends no caption. Missing matches or media-send failures fall back to one short text. An incoming sticker alone is analyzed first; explicit sticker-battle text and an active sticker-battle follow-up retain the direct action path. Private images keep classification; the same prepared image is cached for five minutes under a SHA-256 key and concurrent private requests share one classification call.
- Question-like group messages can enter `group_pending_questions`. Normal triggers still answer only the current message. Rows older than `pendingRetentionDays` (default 30) become `expired`, remain stored, and do not receive an `answered_at` value.
- Schema v4 stores the actual successful information bubble text, `sent/partial/failed` delivery status, and any OneBot message IDs in `reply_audits`.

## 5. Provider Health

Runtime calls write a redacted provider-health snapshot containing provider, target class, stage, result category, attempt count, and latency. Raw credentials, query strings, response bodies, and private endpoints must not be stored.

Read the snapshot without making external requests:

```bash
.venv/bin/python tools/check_provider_status.py --snapshot-only
```

Require a recent healthy snapshot:

```bash
.venv/bin/python tools/check_provider_status.py \
  --snapshot-only \
  --max-age-seconds 600 \
  --require-healthy
```

Actively probe the currently configured providers:

```bash
.venv/bin/python tools/check_provider_status.py --require-healthy
```

HiThink active probes use its bounded API client and report an authentication category when its key is absent; AkShare and yfinance probes run in killable child processes. A-share providers use HiThink-primary/AkShare-fallback order and a closed/open/half-open circuit breaker. The 20-sector A-share and US-share core-stock reports run concurrently under the market command deadline.

## 6. Video Egress And Proxy Configuration

Before live video acceptance, check DNS, TCP, TLS, and HTTP separately:

```bash
.venv/bin/python tools/check_video_egress.py --require-ok
```

Specify a limited target when diagnosing one route:

```bash
.venv/bin/python tools/check_video_egress.py \
  --url https://www.douyin.com/ \
  --timeout 10 \
  --require-ok
```

An HTTP response proves outbound reachability only. It does not prove extraction, download, or upload success. The tool opens independent raw DNS/TCP/TLS probes for diagnostics, then performs the routed HTTP request used for the final egress verdict. If that HTTP(S) request succeeds after an independent raw probe times out, the transport stage is marked `verified_by_http` and the original category remains under `independent_probe`; an HTTP timeout still fails the preflight.

Video proxies are loaded only from the environment variables named by `video.httpProxyEnv` and `video.socksProxyEnv`. The default names are:

```text
QQ_BOT_VIDEO_HTTP_PROXY
QQ_BOT_VIDEO_SOCKS_PROXY
```

Do not write proxy credentials into `config/config.json`, command output, provider snapshots, or audit messages.

Connection timeouts are classified as `network_timeout`. Network failures back off and advance the bounded Douyin/Bilibili domain-family circuit breakers. Douyin short links are resolved once per cache lifetime, and canonical URLs are stored in a bounded TTL cache.

## 7. Controlled Video Upload Acceptance

Normal video handling checks NapCat `upload_group_file` before downloading. Uploads use an explicit `file:///...` URI. The deployment transaction discovers the NapCat QQ process group and prepares the shared cache as bot-owned, NapCat-group-readable mode `2750`; its mount probe runs as the real NapCat identity instead of container root. Long-running jobs send at most one `处理中` notice and one final atomic result. Each URL records platform, stage, attempts, latency, and final result in the audit trail.

The root-only QQ command flow for a small test file is:

```text
/video upload plan <group_id> <cache-relative.mp4>
/video upload apply <group_id> <cache-relative.mp4> <plan_hash> --confirm-group <group_id>
```

Operational rules:

- Use a small, known test video under the configured shared cache.
- Verify the plan target, relative path, file size, expiry, and plan hash.
- Apply once within the short validity window and confirm the exact group ID.
- Treat route success, NapCat capability, upload acknowledgement, and user-visible QQ delivery as separate evidence.

## 8. Speech, Images, And Historical TTS

Speech supports two explicit administrator-selected modes: `audio_speech` calls binary `/v1/audio/speech`, while `chat_completions_audio` calls `/v1/chat/completions` and decodes `choices[0].message.audio.data`. Chat Audio is accepted only when Base64, byte limit, file signature, and normalized transcript validation pass. Set `randomReplyEnabled=false` to serve explicit voice commands only. Provider generation has bounded retries; QQ record delivery is attempted once, and a timeout is recorded as unknown rather than automatically resending or adding duplicate text. Image generation and editing use the configured image endpoints. Keep media features disabled until the provider and model have been verified independently.

The historical local TTS service is not part of the public runtime. Existing installations can inspect its retirement state:

```bash
.venv/bin/python tools/manage_tts_retirement.py status
```

The management lifecycle is:

```text
plan -> apply -> status
                rollback
                rehearse
                delete
```

`apply`, `rollback`, rehearsal, and deletion change runtime state. Require a reviewed plan, an operation window, rollback material, retention expiry, a successful restore rehearsal, and explicit deletion approval. A service is retired only when it is both inactive and disabled.

## 9. Runtime Inspection

Inspect the main runtime without printing raw messages or secrets:

```bash
.venv/bin/python tools/inspect_runtime_status.py --summary --limit 5
```

For an acceptance gate that requires the bot, NapCat WebUI, and OneBot reverse WebSocket to be ready:

```bash
.venv/bin/python tools/inspect_runtime_status.py \
  --summary \
  --require-ready \
  --limit 5
```

Provider health, video egress, successful download, NapCat upload, visible QQ delivery, and recovery are separate gates. A green runtime summary does not imply all external capabilities are healthy.

## 12. Current Feature Status

Automatic Douyin/Bilibili downloads, `#政事/#财经/#科技/#金融`, news-subscription commands, and the scheduled news worker are disabled. Their historical modules and tables remain only for rollback, audit, and maintenance compatibility.

Individual A-shares can also be queried with forms such as `#比亚迪`, a legal company name, or `#牧原股份（牧原）`; a provider must return a verified canonical symbol, and unresolved names are never guessed. HiThink is the A-share primary provider and AkShare is the only fallback. AkShare uses Tencent Securities for batch and name lookups, and an explicit canonical code such as `000001.SZ` uses its Tencent quote fast path. Missing, non-positive, and suspended prices are unavailable rather than current market data. `#A股` and `#美股` produce 20 sector messages with 10 stocks per sector. Each row includes stock name, code, previous close, current price, and percentage change. When the data contains at least five actual gainers and five actual losers, the command selects those groups. During pre-market, closed, or one-sided sessions it instead labels the top five and bottom five as relative leaders/laggards; it never relabels a negative move as an actual gain. The default provider deadline is 15 seconds within a 20-second command deadline, and yfinance batches are split into groups of 25 with bounded concurrent workers.

The optional `usageRankingReport` worker starts at `17:15` in `Asia/Shanghai` when enabled. Wakeups recheck the clock; a missed one-minute start window is skipped instead of sending late. It refreshes credentials from an ignored `0600` token file, requests the current day's ranking, renders a local PNG with a configured font, sends it to the configured private recipient, and deletes the PNG after success or failure. SQLite schema v5 claims each recipient/date slot before external work; attempted or ambiguous deliveries are never automatically retried. The public template uses `https://api.example.com`; replace it with your own audited admin endpoint in a private deployment.

### Codex Runway

When enabled, `codexRunway` runs every `21600` seconds from the bot's monotonic startup anchor, first sending after six hours. Reconnection keeps that anchor, send duration does not shift later deadlines, and missed intervals are not replayed in a burst. Restarting the bot starts a new six-hour cycle. SQLite schema v5 claims each startup/interval slot before external work; attempted or ambiguous deliveries are not automatically retried. Trusted `x.com` and `twitter.com` event text is translated completely into Chinese. The application does not truncate translated text; if OneBot explicitly rejects a message as too long, the complete text is split only at transport boundaries.

Legacy `intervalSeconds`, `excerptChars`, and `maxMessageChars` values are migration inputs only and must not be used to restore the old schedule or display limits.

### Offline Profile Rebuilds

`tools/build_style_profile.py` builds a bot-owned character from aggregate low-sensitivity history metrics. `tools/rebuild_group_profiles.py` recomputes one group's member profiles from a bounded database window. Keep raw exports, local profiles, databases, and reports outside Git; back up SQLite first and independently read back the target group after any profile write.

## 14. Private Operator Dashboard

Run `tools/run_dashboard.py` on `127.0.0.1:3011` behind an authenticated HTTPS tunnel. Create a password hash interactively with `tools/dashboard_password.py` (minimum 16 characters); keep the resulting file private. Configure the exact HTTPS origin, hash path, NapCat root, and separate OneBot/WebUI token files and HTTP port. Never expose the raw dashboard, WebUI, or OneBot ports, or grant the dashboard Docker/sudo privileges.

The page polls QQ/Bot status and CPU, memory, and disk every 10 seconds. If QQ is not reported online, it attempts to show an **existing** QR from the last 180 seconds; it does **not** generate a new QR automatically. Use **Refresh QR** for a missing or expired QR. Online QQ hides the QR and the refresh endpoint rejects requests. Unknown status is not proof of logout. Anonymous `/api/status` and `/api/qq/qr` should return 401, while HTTPS `/login` returns 200; a successful login still needs confirmation on the QQ client and a fresh `online/good` readback.

## 2. 配置密钥、权限与画像

真实密钥只放在私有 `.env` 或服务管理器，不放 JSON、脚本和命令输出。示例环境变量 `QQ_BOT_MODEL_API_KEY`、`QQ_BOT_HITHINK_API_KEY`、`QQ_BOT_ONEBOT_TOKEN`、视频代理与 `QQ_BOT_CONFIG_PATH` 均不得提交真实值。将 `config/config.json` 中的 `BOT_QQ`、`ROOT_QQ`、`OWNER_QQ`、`ALLOWED_GROUP_ID`、`https://api.example.com/v1` 和 `your-model-name` 替换为本地私有配置。root 自动具有 owner 和私聊白名单权限；只有 root 能维护 owner 或授权受控视频上传。

同花顺为 A 股主源，AkShare 为唯一备用；AkShare 批量/名称走腾讯证券，规范代码使用快速报价路径，停牌或缺失价格不报告为当前价。公开画像示例只含演示数值。实际部署须从低敏聚合指标生成被忽略的 `persona_profile.local.json` 并更新 `persona.profilePath`；运行时不会自动使用示例画像。

## 3. 连接 OneBot

Bot 使用 `.venv/bin/python bot.py` 运行。NapCat 等 OneBot v11 实现应以相同 token 反向连接 `ws://127.0.0.1:8081/onebot/v11/ws`。除非经过额外网络边界审查，WebUI、OneBot HTTP/WS 与后台应用均保持 loopback，不开放公网。

## 4. 帮助、新闻、行情与搜索

结构化入口包括 `/help`、`#政事/#财经/#科技/#金融`、`#A股/#美股`、个股名称或代码、`#chat 查一下 <关键词> [--page N]` 和 `#chat 帮我查一下`。当前新闻分类、新闻订阅、定时新闻和自动短视频下载处于停用状态；保留的历史代码不能视为已恢复上线。

`/help` 一次发送完整入口；新闻/搜索按中文标题、来源、时间/摘要和 URL 的原子块发送，超长结果保留分页。完整消息先尝试发送，只有 OneBot 明确拒绝长度才做一次摘要重试。单一异常长 URL（超过 2048 字符）标记不可用，不拆散信息块。行情并发读取 20 个板块候选，报告数据时间、来源和耗时；缺价与停牌明确不可用。URL、小数和缩写不会被普通句子切分误拆。

普通群聊不走项目级安全分类，私聊安全与低敏长期存储保持启用。普通短回复最多 320 tokens、默认 18 秒截止；技术解释用单条长消息，休眠会话关系判别最多 32 tokens、默认 1.2 秒。看图独立 30 秒截止，仅下载可信 QQ CDN HTTPS 图像（上限 8 MiB）；GIF/WebP 转有界 PNG 首帧。成功分析后只发匹配且安全的本地表情包，缺失或发送失败回退短文本。私聊图片分类可在五分钟内复用，历史待补答问题 30 天过期但保留记录；信息发送审计记录成功内容、状态和可用消息 ID。

## 6. 视频出站与代理

真实视频验收前分阶段确认 DNS、TCP、TLS 与最终路由 HTTP：

```bash
.venv/bin/python tools/check_video_egress.py --require-ok
.venv/bin/python tools/check_video_egress.py --url https://www.douyin.com/ --timeout 10 --require-ok
```

HTTP 通并不等于提取、下载或 QQ 上传成功。若独立直连探针超时而路由 HTTP 成功，传输阶段为 `verified_by_http`，原始故障留在 `independent_probe`；HTTP 超时仍失败。视频代理只从 `QQ_BOT_VIDEO_HTTP_PROXY` / `QQ_BOT_VIDEO_SOCKS_PROXY` 环境变量读取，不把代理密码写入配置、命令输出或审计。网络超时标为 `network_timeout`，受抖音/B 站域名族熔断及退避约束；短链/规范 URL 使用有界缓存。

## 7. 受控视频上传验收

正常处理先确认 NapCat 的 `upload_group_file` 能力，再下载；上传使用 `file:///...` 绝对 URI。共享缓存设置为 Bot 所有、NapCat 组可读的 `2750` 权限，并以真实 NapCat 身份探测挂载而非容器 root。长任务至多一条“处理中”提示和一条最终原子结果，审计按 URL 记录平台、阶段、次数、耗时与最终状态。

仅 root 可针对小型已知测试文件执行：

```text
/video upload plan <group_id> <cache-relative.mp4>
/video upload apply <group_id> <cache-relative.mp4> <plan_hash> --confirm-group <group_id>
```

先核对群号、缓存相对路径、大小、有效期与哈希，只在有效窗口内执行一次。路由成功、NapCat 支持、上传回执与 QQ 客户端实际可见是四层不同证据。

## 8. 语音、图片与历史 TTS

显式语音可选择 `audio_speech`（`/v1/audio/speech` 二进制）或 `chat_completions_audio`（从 `/v1/chat/completions` 的 `choices[0].message.audio.data` 解码）。Chat Audio 须通过 Base64、大小、文件签名与规范 transcript 校验。`randomReplyEnabled=false` 仅处理显式朗读；生成失败有界重试，QQ 语音投递只尝试一次，不确定超时不能自动重发或追加重复文本。图片生成/编辑使用已配置端点，启用前要独立验证提供方/模型。

旧本地 TTS 服务不属于当前公开运行时。历史实例可只读检查：

```bash
.venv/bin/python tools/manage_tts_retirement.py status
```

生命周期为 `plan -> apply -> status`，并有 `rollback/rehearse/delete`；后四类变更需审查计划、操作窗口、回滚材料与权限，删除还需保留期届满及恢复演练。服务只有 inactive 且 disabled 才算真正退役。

## 9. 运行状态检查

## 12. 当前功能状态

自动抖音/B 站下载、`#政事/#财经/#科技/#金融`、新闻订阅命令与定时新闻当前停用；历史模块和表仍保留供回滚、审计与维护。个股可按代码、简称/公司名、括号别名查询，必须由提供方返回已验证规范代码，不能猜测未解析名称。同花顺是 A 股主源，AkShare 是唯一备用，腾讯证券处理批量/名称与规范代码快速报价；缺价、非正价格及停牌不视为当前行情。

`#A股` 和 `#美股` 各可生成 20 条板块消息、每板块 10 个候选，包含名称、代码、昨收、现价与涨跌幅。实际涨/跌各满五只才按真实赢家/输家分组；盘前、休市或单边行情按相对前五/后五明确标注，不把跌幅冒充上涨。默认提供方 15 秒截止、命令总截止 20 秒；yfinance 以 25 只分批并行。

可选 `usageRankingReport` 在北京时间 17:15 起点运行，错过一分钟窗口则跳过；从被忽略的 0600 token 文件取凭据、请求当日排行、渲染本地 PNG 并投递私聊，之后删除临时 PNG。schema v5 先 claim 收件人/日期，不确定发送不自动补发。公开模板使用示例 API 地址，生产须换成私有已审计管理端点。

可选 `codexRunway` 从 Bot 单调启动时间起每 21600 秒运行，首次六小时后。重连不重置锚点，发送耗时不漂移，漏过周期不突发补发，重启 Bot 则开启新周期；schema v5 先 claim 周期/收件人。不截断可信 X/Twitter 原文的中文翻译，只有 OneBot 明确拒绝长度才按传输边界拆分。旧 `intervalSeconds`、`excerptChars` 与 `maxMessageChars` 只是迁移输入，不允许恢复旧排程。

离线画像工具 `tools/build_style_profile.py` 从低敏聚合历史指标构建 Bot 自有角色，`tools/rebuild_group_profiles.py` 针对指定群和有界时间窗重算群成员画像。原始导出、私有画像、数据库及报告不能进 Git；写画像前做一致备份，写后独立读回。

## 13. 发布安全

公开导出仅包含 `app/`、`config/`、`scripts/`、`tools/`、`.env.example`、`.gitattributes`、`.gitignore`、`bot.py`、`pyproject.toml`、`README.md` 与 `操作手册.md`。不得发布 `docs/`、`tests/`、私有设计/手册、`.env`、真实 JSON 配置、画像、本地数据库/备份/日志、运行制品、二维码、NapCat 登录/缓存、私有截图、QQ/群号、私有地址或凭据。推送前从独立脱敏导出扫描文件形状和私有字面值，不把私有开发树镜像到 GitHub。

## 14. 私有运行后台

后台由 `tools/run_dashboard.py` 在 loopback `127.0.0.1:3011` 提供，由鉴权 HTTPS tunnel 对外访问。口令至少 16 字符，使用 `tools/dashboard_password.py` 交互式生成私有哈希；后台需 HTTPS origin、私有哈希文件、NapCat 根目录、OneBot/WebUI 独立 token 文件及端口环境变量。不要开放原生 WebUI、OneBot HTTP/WS、后台应用端口，也不要给后台 Docker/sudo 权限。

网页每 10 秒读取 QQ 登录、Bot、CPU、内存、磁盘。QQ 未被报告在线时会尝试显示已有且不超过 180 秒的二维码；**不会自动生成新的二维码**。二维码缺失/过期请点“刷新二维码”，而不是重启在线 QQ；在线时二维码隐藏，刷新接口拒绝。状态未知不能等同确定掉线。匿名 `/api/status`、`/api/qq/qr` 应返回 401，HTTPS `/login` 返回 200；真实扫码由用户在 QQ 客户端完成后再独立读回 `online/good`。
