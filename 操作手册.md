# QQ Bot Public Operation Manual

This manual describes how to run the sanitized QQ Bot project. Replace all placeholders with your own values. Do not publish private QQ IDs, group IDs, API keys, tokens, server passwords, databases, logs, QR codes, or NapCat login state.

## 1. Prepare Runtime Files

```powershell
Copy-Item .env.example .env
Copy-Item config\config.example.json config\config.json
Copy-Item config\persona_profile.example.json config\persona_profile.local.json
```

Fill `.env` with your model API key and optional OneBot token. Fill `config/config.json` with your own QQ IDs, allowlists, model endpoint, and runtime paths.

## 2. Install And Start Locally

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -e .[dev]
python bot.py
```

Check status:

```powershell
python tools\inspect_runtime_status.py --limit 5
```

## 3. NapCat Reverse WebSocket

Set NapCat OneBot V11 reverse WebSocket to:

```text
ws://YOUR_SERVER_IP:8080/onebot/v11/ws
```

For same-host deployment:

```text
ws://127.0.0.1:8080/onebot/v11/ws
```

After login, `napcat_to_bot_established` should become `true`.

## 4. Permissions

Root users are configured by `qq.rootUserIds`. Root automatically has owner permission and private allowlist permission.

Owners/root can use management commands in private chat. Non-owners stay silent for management commands. Only root can manage owners.

Root-only owner management:

```text
/owner add <qq>
/owner remove <qq>
/owner list
```

Allowlist management:

```text
/allow private add <qq>
/allow private remove <qq>
/allow private list
/allow group add <group_id>
/allow group remove <group_id>
/allow group list
```

## 5. Help And Runtime Commands

Send `/help` in private chat as owner/root to view the complete command list.

Common commands:

```text
/status
/memory
/memory clear
/audit last
/reload profile
/ping model
/mute status
/mute clear
/mute clear <group_id>
```

## 6. Private Reminders

Natural-language reminders are private-chat only. Group reminder requests stay silent.

Examples:

```text
10 minutes later remind me to drink water
/remind 10 minutes later check the service
/remind list
/remind cancel <id>
```

Empty reminder requests ask for reminder content instead of calling the model.

## 7. Group Replies

Group replies use threaded QQ style:

- The first bubble replies to the original message, mentions the sender, and includes text.
- Later bubbles send plain text.
- Same-group reply tasks are serialized with at least 1.5 seconds between sends.
- Normal group triggers answer only the current message. Historical pending questions are answered only when the user explicitly asks to backfill, with at most 3 pending questions per request.

## 8. Model Context Enhancement

Before model calls, the bot prepares a short low-risk context block. Depending on the message, it may include:

- Current message restatement.
- Relevant long-term memory.
- Group context summary.
- Quoted message summary.
- Matched group semantic terms or nicknames.
- Sticker/image analysis result.
- Reply mode hint, such as short text, long text, or code block.

High-risk or unrelated data should not be injected into prompts.

## 9. Sticker Assets

Allowed private chats and allowlisted groups can save NapCat-marked sticker, emoji, animated-sticker, and sticker-like image assets into one shared pool:

- Files are stored under `data/stickers/global/`.
- Metadata is stored in SQLite table `sticker_assets`.
- Semantic analysis is stored in `sticker_asset_analysis` when the configured model supports image input.
- Assets are deduplicated by content hash.
- The pool is capped at 3500 unique assets.
- Plain images are not stored unless NapCat/OneBot metadata marks them as sticker-like.
- Sticker requests use the local pool directly. If no usable asset exists, the bot replies `没有`.
- Text repeat and sticker repeat are independent paths.
- `data/stickers/` is runtime data and must not be committed.

## 10. Server Scripts

Linux helper scripts live in `scripts/server/`. Override defaults with environment variables:

```bash
export QQ_BOT_ROOT=/opt/qq_bot
export QQ_BOT_SERVICE=qq-bot.service
export NAPCAT_CONTAINER=napcat
```

Common commands:

```bash
bash scripts/server/status.sh
bash scripts/server/restart_all.sh
bash scripts/server/tail_logs.sh
bash scripts/server/backup_runtime.sh
```

Install log rotation by adapting the template:

```bash
sudo cp scripts/server/logrotate-qq-bot.conf /etc/logrotate.d/qq-bot
sudo logrotate -d /etc/logrotate.d/qq-bot
```

## 11. Database Maintenance

```bash
python tools/backup_db.py --db data/bot.db --backup-dir data/backups
python tools/export_audits.py --db data/bot.db --output audits.jsonl
python tools/vacuum_db.py --db data/bot.db --backup-dir data/backups
```

## 12. Troubleshooting

- Private chat silent: check `allowedPrivateUserIds` or root config.
- Group chat silent: check `allowedGroupIds`, @ mention parsing, group mute, queue status, and rate limits.
- Model failure: inspect `/status`, `/audit last`, or `tools/inspect_runtime_status.py`.
- Image understanding unavailable: confirm the configured OpenAI-compatible model supports image input, otherwise the bot should fall back safely.
- NapCat disconnected: check QQ login state and the reverse WebSocket URL.

## 13. Publish Safety

Before pushing public code, scan for private values and remove runtime files. The public repository should contain code, templates, README, and this public operation manual only.
