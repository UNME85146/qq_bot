# QQ Bot Public Operation Manual

This manual describes how to run the sanitized QQ Bot project. Replace all placeholders with your own values. Do not publish private QQ IDs, group IDs, API keys, tokens, server passwords, databases, logs, QR codes, or NapCat login state.

## 1. Prepare Runtime Files

```powershell
Copy-Item .env.example .env
Copy-Item config\config.example.json config\config.json
Copy-Item config\persona_profile.example.json config\persona_profile.local.json
```

Fill `.env` with your model API key and optional OneBot token. Fill `config/config.json` with your own QQ IDs, allowlists, model endpoint, and runtime paths.

## 2. Start Locally

```powershell
.\.venv\Scripts\Activate.ps1
python bot.py
```

Check status:

```powershell
python tools\inspect_runtime_status.py --limit 5
```

## 3. NapCat Reverse WebSocket

Set NapCat OneBot V11 reverse WebSocket to:

```text
ws://YOUR_SERVER_IP:8080/onebot/v11/ws
```

For same-host deployment:

```text
ws://127.0.0.1:8080/onebot/v11/ws
```

After login, `napcat_to_bot_established` should become `true`.

## 4. Private Reminders

Reminders are private-chat only. Examples:

```text
?????????
/remind ?????????
/remind list
/remind cancel <id>
```

Empty reminder requests such as `??????` or `/remind ???????` should ask for reminder content instead of calling the model. Group reminder requests stay silent.

## 5. Owner/Root Commands

Use `/help` in private chat as owner/root to view commands. Root users are configured by `qq.rootUserIds` and automatically have owner and private allowlist permission.

Root-only owner management:

```text
/owner add <qq>
/owner remove <qq>
/owner list
```

Allowlist management:

```text
/allow private add <qq>
/allow private remove <qq>
/allow private list
/allow group add <group_id>
/allow group remove <group_id>
/allow group list
```

## 6. Server Scripts

Linux helper scripts live in `scripts/server/`. Override defaults with environment variables:

```bash
export QQ_BOT_ROOT=/opt/qq_bot
export QQ_BOT_SERVICE=qq-bot.service
export NAPCAT_CONTAINER=napcat
```

Common commands:

```bash
bash scripts/server/status.sh
bash scripts/server/restart_all.sh
bash scripts/server/tail_logs.sh
bash scripts/server/backup_runtime.sh
```

## 7. Sticker Assets

Allowed private chats and allowlisted groups can automatically save NapCat-marked sticker, emoji, animated-sticker, and sticker-like image assets into the shared sticker pool:

- Files are stored under `data/stickers/global/`.
- Metadata is stored in SQLite table `sticker_assets`.
- Allowlisted group media is still saved while the group is muted; mute only prevents replies, repeat behavior, and model calls.
- Assets are deduplicated by content hash.
- The pool is capped at 3500 unique assets; duplicate assets do not consume new capacity.
- Sticker requests such as `send a sticker` or `do you have stickers` use the local pool directly: if any usable asset exists, the bot randomly sends one; if none exists, it replies `没有` and does not call the model.
- Plain images are not stored unless NapCat/OneBot metadata marks them as stickers or emoji-like assets, for example `sticker`, `emoji`, `marketface`, `mface`, or sticker-related summary text.
- Text repeat and sticker repeat are separate paths: plain text only repeats after the same low-risk short text appears consecutively in the same group; sticker repeat uses stored sticker assets and does not depend on text repeat counts.
- `data/stickers/` is runtime data and must not be committed.

## 8. Database Maintenance

```bash
python tools/backup_db.py --db data/bot.db --backup-dir data/backups
python tools/export_audits.py --db data/bot.db --output audits.jsonl
python tools/vacuum_db.py --db data/bot.db --backup-dir data/backups
```

## 9. Troubleshooting

- Private chat silent: check `allowedPrivateUserIds` or root config.
- Group chat silent: check `allowedGroupIds`, @ mention parsing, group mute, and rate limits.
- Model failure: inspect `/status`, `/audit last`, or `tools/inspect_runtime_status.py`.
- NapCat disconnected: check QR/login state and reverse WebSocket URL.

## 10. Publish Safety

Before pushing public code, scan for private values and remove runtime files. The public repository should contain code and templates only.
