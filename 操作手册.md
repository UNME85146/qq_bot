# QQ Bot Public Operation Manual

This manual covers the sanitized public distribution. Adapt paths, service names, QQ identifiers, and providers to your own environment. Never copy private runtime values into the public repository.

## 1. Install

Create a Python 3.12 or 3.13 virtual environment and install the required extras:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[market,video]'
cp .env.example .env
cp config/config.example.json config/config.json
```

The `market` extra installs AkShare and yfinance. The `video` extra installs yt-dlp and SOCKS proxy support. Install `ffmpeg` with your operating system package manager before enabling video downloads.

## 2. Configure Secrets And IDs

Keep literal secrets in `.env` or your service manager, never in JSON or scripts:

```dotenv
QQ_BOT_MODEL_API_KEY=
QQ_BOT_ONEBOT_TOKEN=
QQ_BOT_VIDEO_HTTP_PROXY=
QQ_BOT_VIDEO_SOCKS_PROXY=
QQ_BOT_CONFIG_PATH=config/config.json
```

Set these placeholders in `config/config.json`:

```text
BOT_QQ
ROOT_QQ
OWNER_QQ
ALLOWED_GROUP_ID
https://api.example.com/v1
your-model-name
```

Root users automatically have owner and private-allowlist permission. Only root can manage owners or authorize the controlled video-upload acceptance path.

Optional integrations remain disabled until their `enabled` flag and provider settings are configured. Do not treat a configured route as proof that its provider is reachable.

The public `config/persona_profile.example.json` contains numeric demonstration metrics and `SOURCE_QQ` only. Generate an ignored `persona_profile.local.json` for a real deployment, update `persona.profilePath`, and do not commit source identifiers or chat history. Runtime does not fall back to the example profile automatically.

## 3. Connect OneBot

Run the bot:

```bash
.venv/bin/python bot.py
```

Configure NapCat or another OneBot v11 implementation to connect by reverse WebSocket:

```text
ws://127.0.0.1:8081/onebot/v11/ws
```

Use the same access token on both sides. Keep the listener on loopback unless your deployment has a separately reviewed network boundary.

## 4. Help, News, Markets, And Search

The following group features use structured delivery instead of normal short-chat bubbles:

```text
/help
#政事
#财经
#科技
#金融
#A股
#美股
#chat 查一下 <query> [--page N]
```

Behavioral guarantees:

- `/help` is one complete message containing all eight entry lines.
- Each news category sends every non-empty set of verifiable atomic blocks containing a Chinese title, source, Beijing time, and URL.
- Search sends every non-empty set of verifiable atomic blocks containing a Chinese title, source, Chinese summary, and URL. Larger result sets retain the existing paging rules without silently dropping a short tail.
- A-share and US-share commands concurrently fetch 20 sector core stocks in one report. They show sector tendency, data time, source, and command latency without per-stock percentage changes.
- URLs, decimals, and common abbreviations are protected from sentence splitting.
- Titles, summaries, times, statuses, and explanations are Chinese. Source names, URLs, and command syntax may retain their original form.
- Complete information messages are attempted first. Only an explicit OneBot message-length rejection triggers one compact-summary retry; other send failures do not trigger this fallback.
- A single external URL is accepted up to 2048 characters. An abnormal longer URL is marked unavailable without splitting its atomic block.

Scheduled news commands:

```text
#新闻订阅
#新闻订阅 HH:MM
#新闻订阅状态
#新闻退订
```

Feeds fail independently. Delivery checkpoints are at-least-once: after a OneBot acknowledgement followed by a process crash before the SQLite cursor commit, the last block can be repeated.

Group chat behavior:

- Group reply routes have no project-level safety classifier. Group text, image understanding/generation, explicit voice, search/evaluation, repeats, stickers, and pending enqueue are not blocked or rewritten by project safety rules. Private chat and low-sensitivity long-term storage keep their existing controls.
- Normal short group calls use at most 320 completion tokens, forward the configured reasoning effort, and use `conversationSessions.groupModelTimeoutSeconds` (default 18 seconds) as a hard deadline. Image understanding uses an independent breaker and `visionTimeoutSeconds` (default 30 seconds).
- Dormant-session relation checks use at most 32 tokens and `conversationSessions.relationTimeoutSeconds` (default 1.2 seconds).
- Triggered OneBot images resolve a fresh URL with `get_image`, allow only trusted QQ CDN HTTPS downloads up to 8 MiB, and inline JPEG/PNG; GIF/WebP are converted to a bounded PNG first frame with ffmpeg. Group images then go directly to the multimodal description call. Private images keep classification; the same prepared image is cached for five minutes under a SHA-256 key and concurrent private requests share one classification call.
- Question-like group messages can enter `group_pending_questions`. Normal triggers still answer only the current message. Rows older than `pendingRetentionDays` (default 30) become `expired`, remain stored, and do not receive an `answered_at` value.
- Schema v4 stores the actual successful information bubble text, `sent/partial/failed` delivery status, and any OneBot message IDs in `reply_audits`.

## 5. Provider Health

Runtime calls write a redacted provider-health snapshot containing provider, target class, stage, result category, attempt count, and latency. Raw credentials, query strings, response bodies, and private endpoints must not be stored.

Read the snapshot without making external requests:

```bash
.venv/bin/python tools/check_provider_status.py --snapshot-only
```

Require a recent healthy snapshot:

```bash
.venv/bin/python tools/check_provider_status.py \
  --snapshot-only \
  --max-age-seconds 600 \
  --require-healthy
```

Actively probe the currently configured providers:

```bash
.venv/bin/python tools/check_provider_status.py --require-healthy
```

Active market probes run providers in killable child processes. A-share providers use fallback order and a closed/open/half-open circuit breaker. The 20-sector A-share and US-share core-stock reports run concurrently under the market command deadline.

## 6. Video Egress And Proxy Configuration

Before live video acceptance, check DNS, TCP, TLS, and HTTP separately:

```bash
.venv/bin/python tools/check_video_egress.py --require-ok
```

Specify a limited target when diagnosing one route:

```bash
.venv/bin/python tools/check_video_egress.py \
  --url https://www.douyin.com/ \
  --timeout 10 \
  --require-ok
```

An HTTP response proves outbound reachability only. It does not prove extraction, download, or upload success. The tool opens independent raw DNS/TCP/TLS probes for diagnostics, then performs the routed HTTP request used for the final egress verdict. If that HTTP(S) request succeeds after an independent raw probe times out, the transport stage is marked `verified_by_http` and the original category remains under `independent_probe`; an HTTP timeout still fails the preflight.

Video proxies are loaded only from the environment variables named by `video.httpProxyEnv` and `video.socksProxyEnv`. The default names are:

```text
QQ_BOT_VIDEO_HTTP_PROXY
QQ_BOT_VIDEO_SOCKS_PROXY
```

Do not write proxy credentials into `config/config.json`, command output, provider snapshots, or audit messages.

Connection timeouts are classified as `network_timeout`. Network failures back off and advance the bounded Douyin/Bilibili domain-family circuit breakers. Douyin short links are resolved once per cache lifetime, and canonical URLs are stored in a bounded TTL cache.

## 7. Controlled Video Upload Acceptance

Normal video handling checks NapCat `upload_group_file` before downloading. Uploads use an explicit `file:///...` URI. The deployment transaction discovers the NapCat QQ process group and prepares the shared cache as bot-owned, NapCat-group-readable mode `2750`; its mount probe runs as the real NapCat identity instead of container root. Long-running jobs send at most one `处理中` notice and one final atomic result. Each URL records platform, stage, attempts, latency, and final result in the audit trail.

The root-only QQ command flow for a small test file is:

```text
/video upload plan <group_id> <cache-relative.mp4>
/video upload apply <group_id> <cache-relative.mp4> <plan_hash> --confirm-group <group_id>
```

Operational rules:

- Use a small, known test video under the configured shared cache.
- Verify the plan target, relative path, file size, expiry, and plan hash.
- Apply once within the short validity window and confirm the exact group ID.
- Treat route success, NapCat capability, upload acknowledgement, and user-visible QQ delivery as separate evidence.

## 8. Speech, Images, And Historical TTS

Speech uses an administrator-configured OpenAI-compatible `/v1/audio/speech` endpoint. Image generation and editing use the configured image endpoints. Keep both disabled until the provider and model have been verified independently.

The historical local TTS service is not part of the public runtime. Existing installations can inspect its retirement state:

```bash
.venv/bin/python tools/manage_tts_retirement.py status
```

The management lifecycle is:

```text
plan -> apply -> status
                rollback
                rehearse
                delete
```

`apply`, `rollback`, rehearsal, and deletion change runtime state. Require a reviewed plan, an operation window, rollback material, retention expiry, a successful restore rehearsal, and explicit deletion approval. A service is retired only when it is both inactive and disabled.

## 9. Runtime Inspection

Inspect the main runtime without printing raw messages or secrets:

```bash
.venv/bin/python tools/inspect_runtime_status.py --summary --limit 5
```

For an acceptance gate that requires the bot, NapCat WebUI, and OneBot reverse WebSocket to be ready:

```bash
.venv/bin/python tools/inspect_runtime_status.py \
  --summary \
  --require-ready \
  --limit 5
```

Provider health, video egress, successful download, NapCat upload, visible QQ delivery, and recovery are separate gates. A green runtime summary does not imply all external capabilities are healthy.

## 10. Generic Deployment

Public deployment helpers use placeholders:

```text
your-server-ip
your-server-user
/opt/qq_bot
```

Review every generated plan before any apply. Keep configuration, database, virtual environment, service units, and rollback data outside public version control. Production restart, migration, public ingress, login recovery, and cleanup should each have explicit authorization and post-action validation.

## 11. Verification

Compile the public export:

```bash
.venv/bin/python -m compileall -q app bot.py tools
```

Load the example configuration without a real key:

```bash
QQ_BOT_MODEL_API_KEY=placeholder-for-import-check \
QQ_BOT_CONFIG_PATH=config/config.example.json \
.venv/bin/python -c 'import bot; import nonebot; print(nonebot.get_driver().type)'
```

The complete automated test suite lives in the private development repository. Test success is local evidence only; live QQ and provider acceptance must be recorded separately.

## 12. Current Feature Status

Automatic Douyin/Bilibili downloads, `#政事/#财经/#科技/#金融`, news-subscription commands, and the scheduled news worker are disabled. Their historical modules and tables remain only for rollback, audit, and maintenance compatibility.

`#A股` and `#美股` produce 20 sector messages with 10 stocks per sector. Each row includes stock name, code, previous close, current price, and percentage change. When the data contains at least five actual gainers and five actual losers, the command selects those groups. During pre-market, closed, or one-sided sessions it instead labels the top five and bottom five as relative leaders/laggards; it never relabels a negative move as an actual gain. The default provider deadline is 15 seconds within a 20-second command deadline, and yfinance batches are split into groups of 25 with bounded concurrent workers.

The optional `usageRankingReport` worker runs at `17:30` in `Asia/Shanghai` when enabled. It refreshes credentials from an ignored `0600` token file, requests the current day's ranking, renders a local PNG with a configured font, sends it to the configured private recipient, and deletes the PNG after success or failure. The public template uses `https://api.example.com`; replace it with your own audited admin endpoint in a private deployment.

## 13. Publish Safety

Before publishing, ensure the export contains only:

```text
app/
config/
scripts/
tools/
.env.example
.gitattributes
.gitignore
bot.py
pyproject.toml
README.md
操作手册.md
```

Do not publish `docs/`, `tests/`, private manuals/designs, `.env`, live JSON configuration, local persona profiles, databases, backups, logs, runtime artifacts, QR codes, NapCat cache/login state, private screenshots, QQ/group IDs, private endpoints, or credentials.
